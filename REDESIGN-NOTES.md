# Notes for whoever (or whatever AI) is redesigning this

This is a single self-contained `index.html` (no build step, no external JS
dependencies beyond two Google Fonts loaded via `<link>` tags). It's a personal
retirement-projection calculator with live sliders, a data table, and a
hand-drawn SVG chart, wrapped as an installable PWA (`manifest.json` + `sw.js`).

The owner wants a **visual redesign** ("a better skin"), not new features or
changed math. Please read this before editing, and open your changes as a
branch or pull request rather than pushing straight to `main` — a human
reviews every change before it goes live.

## What's safe to change (pure styling)

- All color values live as CSS custom properties in the `:root { ... }` block
  near the top of `<style>`. Change `--page`, `--panel`, `--panel-2`,
  `--graphite`, `--graphite-2`, `--rule`, `--dim`, `--accent`, `--accent-2`,
  `--verify`, `--revision`. The whole UI, including the chart, re-colors
  automatically from these because the chart's JS reads them at draw time via
  `getComputedStyle(document.documentElement)`.
- Fonts, spacing, border-radius, shadows, card layout, button styles — all
  fair game.
- The little inline SVG icons next to each sidebar section header, and the
  decorative crescent/"moon" graphic in the top header, are purely cosmetic —
  restyle or replace freely.
- The `ACCOUNTS` array near the top of `<script>` (search for `const ACCOUNTS`)
  has 5 hardcoded hex colors, one per investment account, used specifically by
  the chart's ridge lines and the legend swatches. Update these together with
  the CSS palette if you want the chart's account colors to match a new theme.
- The 4 icon PNGs (`icon-192.png`, `icon-512.png`, `icon-512-maskable.png`,
  `apple-touch-icon.png`) and `manifest.json`'s colors/name — free to redesign,
  just keep the same filenames and sizes referenced in `manifest.json` and
  `index.html`'s `<head>`, or update both together.

## Do not change (functionality — breaking these breaks the tool)

- Element `id` attributes. JavaScript finds elements by id (e.g. `#hl-total`,
  `#isosvg`, `#pacegauge`, `#v-bal`, `#dimcap`) to update them live. Renaming
  an id without updating every matching `document.getElementById(...)` /
  `$("...")` call in `<script>` will silently stop that element from updating.
- The general DOM nesting inside `.dimwrap` / `#iso3d` / `#isosvg` — the chart
  is entirely generated by JavaScript (function `drawTerrain`), which clears
  and rebuilds the `<svg>` contents on every input change. Don't wrap
  `#isosvg` in extra elements that would change its measured `clientWidth`.
- Anything inside the single `<script>` block, unless you're intentionally
  changing chart rendering style (see below), not just color.
- Slider `min`/`max`/`step`/`value` attributes on inputs whose ids start with
  `retire` or `ssage` (Retirement Year, Your/Spouse Claim Age) — these sliders
  move over a constrained index (see `RETIRE_MONTHS` / `decodeRetireYM` /
  `SSAGE_MONTHS` in `<script>`) so they only ever land on valid month values.
  Changing the HTML min/max without updating the matching JS constants will
  desync the slider from the displayed value.
- The `<link rel="manifest">`, `<link rel="apple-touch-icon">`, theme-color
  meta tags, and the service-worker registration script near the end of
  `<script>` — these make the PWA installable and offline-capable. They can be
  restyled in *content* (icon files) but the registration/link plumbing itself
  should stay intact.
- `.inputs` and `.results` must keep `min-width:0` in their CSS rules — this
  was a deliberate fix for a real bug where a wide data table blew the layout
  out past the screen width on phones. Removing it will reintroduce that bug.

## If you want to change the chart's drawing style (not just its colors)

The chart is pure SVG, built line-by-line in JavaScript — no charting
library, no canvas, no WebGL (a WebGL/Three.js version was tried earlier and
abandoned because it required an internet-connected CDN and broke offline).
The function to edit is `drawTerrain(snap, retireAge, atRetire)` in
`<script>` — it's commented throughout. It currently renders each of the 5
investment accounts as a "ridge" made of thousands of thin vertical lines (a
line-density elevation/terrain field), with real depth (farther ridges are
inset, raised, and foreshortened) and a shared value scale across all ridges
so heights stay proportionally honest. Please preserve:

- the shared value scale (variable `maxVal`) — normalizing each ridge to its
  own peak was tried and rejected, since it made very different account
  balances look the same size, which is misleading;
- the hover/touch "trace" feature (search for `showHover`) that shows exact
  values under the cursor — this is a functional feature, not decoration;
- real data only — no injected random noise/jitter for visual flair, the
  terrain's shape must stay an honest reflection of the underlying numbers.

## Offline requirement

This app must keep working with no internet connection after the first load
(aside from the two Google Font requests, which degrade gracefully to system
fonts if unavailable). Don't add a CDN dependency for charting/animation/etc.
— that was tried once already and had to be reverted because it broke when
the CDN was unreachable. `sw.js` caches everything needed for offline use; if
you add new files (fonts, images, scripts), add them to the `ASSETS` array in
`sw.js` too, and bump the `CACHE` version string so installed phones actually
pick up the change.

## Workflow

Please make changes on a new branch and open a pull request rather than
pushing to `main` directly, so they can be reviewed before going live on
[dandrews77.github.io/retirement-tracker](https://dandrews77.github.io/retirement-tracker/).
